## 一、编译

- 脚本：`build\build_exe.ps1`（Nuitka `--standalone --onefile --windows-console-mode=disable`）
- 产物：`build\out\MarkSixBot.exe`　37,698,560 字节　2026-11-16 07:19:20
- 打包内嵌：`templates`（网页看板 / 手工记账页）、`tk-inter` 插件（桌面控制台）
- 命令：`build\build_exe.ps1 -SkipClean`（复用 `main.build` 缓存）

### 踩过的坑：onefile 压缩 OOM

第一次编译在最后打包阶段失败：

```
zstandard.backend_c.ZstdError: zstd compress error: Allocation error : not enough memory
```

原因：机器 15.7 GB 内存、打包时可用约 4 GB，而 Nuitka 的 onefile 压缩默认用 **zstd level 22 + 多线程**，要一次性分配 121 MB dist 的压缩缓冲，直接失败。

解决：给 `build_exe.ps1` 的 nuitka 参数加 `--low-memory`（压缩级别降到 3、单线程）。代价是包从约 28.9 MB 涨到 37.5 MB，但一定打得出来。

### 另一个注意点

长时间编译**不要挂在本工具的 shell 后台任务里**（任务会被系统回收，连带杀掉 Nuitka 子进程）。做法是另起独立进程：

```powershell
Start-Process powershell -ArgumentList "-NoProfile","-ExecutionPolicy","Bypass","-File","%TEMP%\build_lowmem.ps1" -WindowStyle Hidden
```

wrapper 里执行 `build_exe.ps1 -SkipClean *> 日志`，并把退出码写进 `.done` 文件，主 shell 只轮询。

## 四、本轮发现并修掉的 bug：`/reset` 只清了澳门号码盘

### 现象

清完账，看板「本期金额」仍显示 **200**，「生肖金额表 · 澳门」鼠仍是 200 平特，而 `records.jsonl` 已经不存在。

### 复现

1. 记一笔整笔注（平特鼠100，走 `others_state.json`）
2. `POST /reset?account=xxx`
3. `GET /api/dashboard` → `grand_total` 仍为 200

### 原因

`main.py::clear_account_dir` 末尾只有一行 `save_data(init_data(), acc)`，也就是**只重写了澳门的 `numbers_state.json`**：

- `numbers_state_hk.json`（香港号码盘）没归零
- `others_state.json` / `others_state_hk.json`（平特 / 连肖 / 二中二…这类整笔注）没归零

删了流水、销了期号，但这两类状态文件原样留着，所以金额挂在那里。

### 修复

```python
save_data(init_data(), acc)
save_data(init_data(), acc, "HK")
save_others({"total": 0.0, "items": []}, acc)
save_others({"total": 0.0, "items": []}, acc, "HK")
```

### 验证

- 进程内：清空前 `others_total=200`，清空后 MO/HK 都 0、`market_totals["ALL"]["total"]=0`
- HTTP 层（源码版 + 新 exe）：`check_all_http.py` 新增断言「reset 后总金额归零」，40/40 通过
- 新 exe 实测：reset 后 `金额=0 整笔=0 笔数=0`

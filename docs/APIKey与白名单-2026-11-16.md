# 采集端 API Key + 白名单（API Key / 到期 / IP）

日期：2026-11-16
涉及工程：`mark-six-bot`（服务端）、`WxPushTool`（采集端）

## 为什么改

原来的推送密钥只能从授权码的 `session_key` 派生，而且**服务端验签只看
`enabled` + `secret`，从来不看 `expire_at`**。后果：

- 客户买一张一天的有效码 → 拿到 secret → 客户端本地校验可被 patch 掉 →
  之后无限期推送。短授权等于买了一把永久钥匙。
- 密钥跟着授权码走，续期重新出码就换密钥，服务端白名单必须跟着改；而
  白名单只由厂商签发工具写（写的是厂商本机路径），客户机器上没法配。

现在改成：**密钥由服务端生成（API Key），有效期和来源 IP 也由服务端把关**。

## 改了什么

### 服务端 `main.py`

| 改动 | 位置 | 说明 |
|---|---|---|
| 白名单条目新增两个可选把关 | `secret_for()` 附近 | `expire_at` 过期拒收（容差 3 天）、`ip_allow` 填了只收名单内 IP；两者为空 = 不限制（老条目零改动） |
| 拒绝原因写清楚 | `_reject_reason()` | 区分“已停用 / 已过期 / IP 不符 / 密钥不对”，日志里直接能看出是哪一道路闸 |
| 来源 IP 不再默认信任 `X-Forwarded-For` | `_client_ip()` | 这个头谁都能自己写，拿它判 IP 白名单等于送一把“填 127.0.0.1 就进来”的钥匙。只有显式设置 `MSB_TRUST_XFF=1`（确实挂了反代）才用 |
| `/api/clients` 输出 `expired` / `ip_allow` | `api_clients()` | 控制台表格要显示 |

IP 支持写法：单 IP（`192.168.1.10`）或网段（`10.0.0.0/24`），逗号/分号/空格/换行都能分隔；
某一条写错只忽略那一条，不会让整条白名单失效。

### 服务端 `server_gui.py`

白名单页新增两个按钮，表格多一列「IP 白名单」：

- **新增** —— 弹窗填：微信号、客户编号、有效期至、IP 白名单、API Key（自动生成 64 位，
  有「重新生成」）。保存后密钥直接进剪贴板，并写进 `config\wx_clients.json`（幂等：同微信号就更新）。
- **编辑** —— 改到期时间 / IP 白名单 / 换 Key。**续期只改日期，Key 一个字节不用动。**
- 有效期列过期会显示「（已过期）」，免得排查“为什么签不过”查半天。

### 采集端 `WxPushTool`

- `src\app.py`：推送密钥取值顺序改为 **配置里的 API Key 优先**，没填才回退授权码
  `session_key` 派生（老客户零改动）。授权校验本身没放松：授权码无效照样不让启动。
- `src\wxpush\gui.py`：授权页新增「服务端 API Key」输入框 + 保存按钮，写进
  `config\app.json` 的 `secret` 字段；留空清空即回退派生。

## 第二轮调整（按确认的三点）

三点分工：授权工具只出授权码；采集端码有效才能监听、每批推送前复验；服务端验 Key / IP / 有效期。

### 授权工具 `tools\license_tool.py`

- 删掉 `upsert_client` / `clients_path` 和签发、续期两处的写白名单调用。签发只出授权码，
  一个字节都不往 `config\wx_clients.json` 写。原来写的是**工程目录**那份，而服务端 EXE 读的是
  `%LOCALAPPDATA%\MarkSixBot\config` —— 日志显示"服务端白名单密钥已替换"，实际改的是一份
  没人读的副本，客户那边照样推不上去。
- 签发/续期的信息栏不再显示 `final_secret`（那串是授权码派生的，现在只有兜底时才用得上），
  改成说明 API Key 在服务端「白名单」页生成。

### 采集端

- **每批推送前复验授权**（`Pusher.guard`）：码到期、换号、码被换成别的号 → 这批不发、
  进死信、回调把整条采集停掉。以前只在启动和每 10 分钟验一次，中间那段窗口里码已经过期
  还在推。
- 配置页 webhook 下面新增「服务端 API Key」，「保存配置」和「保存」都会写进 `secret`。
- 「测试地址」优先用输入框当下这串 Key 签名（不必先保存），401 时直接提示要核对的三件事。
- 授权页原来的 API Key 区块删掉 —— 一页只管一件事：授权码管能不能启动，Key 管服务端认不认。

### 服务端界面

- 「新增」去掉客户编号，只留微信号，并注明**仅用来分辨是谁在推、不参与验签**。
- 有效期默认 `9999-12-31`（不限期），要限期才改。
- 表格最后一列「API Key」显示「复制」，点一下就把该行明文密钥放进剪贴板（列里仍然是打码的）。

### 端到端测试抓到的两个真问题

1. **默认有效期直接把推送打成 500。** 界面默认 `9999-12-31`，而到期判定原本要
   `date + 3 天`，`date(9999,12,31)` 加 3 天溢出 → `OverflowError` → **每一条推送都 500**。
   已改成加不动就等于不限期。
2. **没有缓冲后要确认边界。** 现在按 "有效期至 = 当天为止"：今天到期当天仍收，昨天到期即拒，
   两条都写进用例守着。

## 客户侧操作

**首次安装**

1. 服务端 →「白名单」页 →「新增」：填微信号、有效期（默认不限期）、IP（可空），Key 自动生成
2. 点表格最后一列「复制」把 Key 拷走 → 采集端「配置」页「服务端 API Key」→ 保存
3. 点「测试地址」，服务端回 200 就算链路通了
4. 采集端「授权」页贴授权码 → 开始监听

**续期**

只改服务端那条的「有效期至」，Key 不动；采集端只换授权码。服务端不用动 Key。

**到期**

有效期至哪天，就到那天为止，次日 00:00 起一律拒收 —— **没有缓冲天数**。
服务端按自己的日期判定，客户端把本地日期改了也没用。

注意这两个日期是两回事：**授权码的有效期**由签发工具决定，管采集端能不能用；
**API Key 的有效期**由你在服务端白名单里填，管还收不收它的推送。两者互不影响，
一边到期不会连带另一边。

**换 IP / 加限制**

「编辑」里改 IP 白名单即可。留空 = 全放行。

## 仍然存在的限制（写清楚，不藏）

1. **服务端装在客户机器上，客户是管理员**。他能直接编辑 `config\wx_clients.json`
   把有效期改到 2099，或者在配置里关掉验签。对诚实客户这套规则有效，对恶意客户
   无效 —— 要真正可控，服务端必须托管在自己这边（SaaS 模式）。
2. **采集端的“双保险”变成单保险**。原来 patch 掉授权校验也推不了（没有
   `session_key` 就得不到正确密钥）。现在 API Key 是客户自己填的，patch 掉授权
   校验 + 拿着 Key 就能推。授权校验仍是第一道门，但不再有第二道暗锁。
3. **X-Forwarded-For 默认不信任**。如果以后真挂反代，要设 `MSB_TRUST_XFF=1`，
   否则 IP 白名单永远看到的是反代地址。
4. **exe 还没重编译**。改动目前在源码里；`build\out\MarkSixBot.exe` 仍是 07:19
   那版（不含本次逻辑）。发版前要重跑 `build\build_exe.ps1`（约 70 分钟，
   记得 `--low-memory`）。

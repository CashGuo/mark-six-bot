## 一、你给的口径（我整理成表）

| 写法 | 含义 | 钱落在哪 |
|---|---|---|
| `平特鼠100` | 鼠这一个肖，一共 100 | 鼠 100 |
| `平特鼠牛100` | 鼠+牛两个肖，加起来一共 100 | 每肖 50（共 100） |
| `平特鼠牛各100` | 鼠 100、牛 100 | 每肖各 100（共 200） |
| `鼠二连肖100` / `二连肖鼠100` | 鼠牛这一组连肖，一共 100 | 每肖 50（共 100） |
| `鼠3连肖300` | 鼠牛虎三个肖，一共 300 | 每肖 100（共 300） |
| `鼠牛3连肖各300` | 鼠、牛、虎每个肖各 300 | 每肖各 300（共 900） |
| `鼠牛二中二100` | 平特 6 个号里必须同时有鼠和牛，一注 100 | 整注 100，不摊单肖 |
| `鼠牛虎三中三100` | 平特 6 个号里三个肖都在，一注 100 | 整注 100，不摊单肖 |

「各」有同音字（各 / 各号 / 各码 / 个 / 每 / 各肖…），解析里本来就是按一批格式词识别的，这条不用额外处理。

## 二、现在的实现在做什么（代码实读）

| 玩法 | 现在的行为 | 与你的口径差在哪 |
|---|---|---|
| 平特 | `平特+生肖串` 按整注记，金额就是原文那个数 | `平特鼠100` 对；`平特鼠牛100` 没分肖，`各` 也当整注（应 200） |
| 连肖 | 把生肖的**号码并集**摊成每号单价 | `二连肖鼠100` 会记成 9 个号各 100 = **900**，严重不对 |
| 二中二/三中三 | 只吃数字（`二中二 5 17 各20`），金额=原文总额 | 写生肖（`鼠牛二中二`）**解析不了**，直接失败 |

三条都记在 `others_state*.json`（不进 49 号盘、不影响港澳分盘、撤销按 rec_id 扣），这个架构本身没问题，改的是"钱怎么分"。

## 三、我的判断

**1、平特 —— 可以，落生肖表。**
一条注拆成"每个肖各多少"，进 12 生肖金额表。共 → 平均摊；各 → 每肖各记。

**2、连肖 —— 可以，落生肖表，但清单要保留组合名。**
钱同样按肖记（共摊 / 各记），但连肖本质是"鼠牛这一组"，所以清单里这一行要写 `2连肖 鼠+牛 共100（每肖50）`，生肖表里鼠 50、牛 50。只看生肖表会丢"它们是一条组合"，核对时对不上客户的原话。

**3、二中二 / 三中三 —— 能记，但不建议摊到单肖，建议单独一栏"组合注"。**
理由：
- 它是一注组合（6 个平特号必须同时有鼠和牛），钱买的是"这两个肖同时出"这件事，不是"鼠多少钱、牛多少钱"；
- 摊到单肖后生肖表会算错：`鼠牛二中二100` 摊成鼠 50 牛 50，跟 `平特鼠牛100`（也是鼠 50 牛 50）在表里长得一模一样，可这两个是完全不同的买法；
- 所以我的做法：金额记整注，清单单独列出并标注命中条件「鼠 ∧ 牛（6 个平特号同时出现）」，生肖表不出现这两肖的数字，只在合计里加进去。

**结论**：1、2 用 12 生肖表；3 用"组合注"清单。两类都在合计里，账面总额与客户报的数一致。

## 四、数据怎么存（不动现有账本结构）

现有：`numbers_state*.json` 记 49 个号、`others_state*.json` 记不计号的注（`items` 里已有 `rec_id / play / text / amount / ts`）。

计划在 `items` 每条上**加字段**（老记录没有这些字段，读的时候按"整注不计号"处理，向后兼容）：

```json
{
  "rec_id": "...", "play": "平特", "text": "平特鼠牛100",
  "amount": 100, "ts": "...",
  "kind": "pingte",          // pingte / lianxiao / zhong2 / zhong3
  "zodiacs": ["鼠","牛"],     // 这一注涉及哪几个肖
  "per": {"鼠": 50, "牛": 50},// 每个肖摊到多少（组合注为 null）
  "share": true               // true=摊到生肖表  false=整注不进生肖表
}
```

生肖表的数字 = 该账号该市场 `items` 里 `share=true` 的 `per` 按生肖汇总，不新增文件、不新增第二本账。

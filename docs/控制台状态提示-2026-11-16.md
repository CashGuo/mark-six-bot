# 控制台：启动状态与「未运行」提示（2026-11-16）

## 需求

1. 点「启动服务」要等好几秒才有反应 —— 要有"启动中"的提示；
2. 运行状态（运行中 / 启动中 / 未运行）在界面上要能看到；
3. 服务停着的时候采集端推不进来 —— 要有明确的提示文本，别让人以为界面开着就在收注。

## 改动

### 状态卡回归

顶部那条状态卡重新上屏，但只留**一行**：`● 运行中 / ● 启动中 / ● 未运行` + 一句说明。
端口、看板地址、账号累计那三格仍然不上屏（之前用户嫌占高度），控件照旧创建、
照旧刷新，只是不显示。

### 启动过程

| 环节 | 行为 |
| --- | --- |
| 点「启动服务」 | 按钮立刻变「启动中…」（浅灰底），状态行 `● 启动中`，第二行「正在拉起后台服务…」 |
| 轮询 | 每 700ms 查一次 `/health`，最多等 25 秒（`_wait_ready`） |
| 就绪 | 状态行 `● 运行中`，第二行「服务端已就绪：http://127.0.0.1:8899/」，按钮变回「停止服务」 |
| 进程死了 | 提示「服务进程没起来，去「消息」页看日志」 |
| 25 秒还没响应 | 提示「等了 25 秒端口还没响应，去「消息」页看日志」 |
| 启动途中点停止 | `_starting` 归位，轮询自己收手 |

轮询间隔自适应：启动中 1 秒一次（用户盯着等），其余 5 秒一次。

改之前只查一次（1.2 秒后），冷启动要 8~10 秒，用户点完看不到任何变化 —— 就是"好像要等好几秒"的来源。

### 未运行时的提示

红字：`现在采集端推来的注收不到（采集端会重试一阵，停太久这几条就漏掉了）；点左下「启动服务」恢复`

不写这句的时候，界面看着一切正常（账、期号、号码盘都在），但采集端推什么都进不来。

## 一个必须一并修的坑：临时提示和状态说明抢同一行

第二行（`lb_hint`）以前既被 `_refresh_status` 写状态说明，又被 `_toast` 写临时提示，
两边互相覆盖。实测就看到「● 运行中」旁边挂着「已停止」这种自相矛盾的组合。

改法：

- `_set_hint(text, color)`：状态说明统一走它，记下文本和颜色（`_hint_text` / `_hint_color`），
  没有活动提示时立刻写到界面；
- `_toast(msg)`：写同一行，但起一个 3 秒的定时器，到点调 `_restore_hint()` 把状态说明放回去。

效果：点了停止，先看到「已停止」3 秒，然后自动变回「现在采集端推来的注收不到…」。

## 实测

用隔离实例验证（`MSB_HOME` 指临时目录、端口 8933，不碰真实的 8899 服务和用户账本），
自动走一遍 未运行 → 启动 → 停止 → 再启动，把状态行 / 第二行 / 按钮文本打出来：

| 时刻 | 状态行 | 第二行 | 按钮 |
| --- | --- | --- | --- |
| 刚打开（服务没跑） | ● 未运行（红） | 现在采集端推来的注收不到（…）；点左下「启动服务」恢复 | 启动服务 |
| 刚点启动 | ● 启动中（黄） | 正在拉起后台服务… | 启动中… |
| 启动 10 秒后 | ● 运行中（绿） | 服务端已就绪：http://127.0.0.1:8933/ | 停止服务 |
| 停止 5 秒后 | ● 未运行（红） | 现在采集端推来的注收不到（…）；点左下「启动服务」恢复 | 启动服务 |
| 再启动瞬间 | ● 启动中（黄） | 正在拉起后台服务… | 启动中… |

另外在真机（用户桌面）上截图确认状态卡排版正常、没有把下面的号码盘挤坏。

# 首次安装链路检查与两端重编（2026-11-17）

## 这次查什么

从「客户第一次装这个系统」的角度，把整条链路逐段走了一遍：

服务端首次启动 → 配置 → 白名单 → 采集端首次安装 → 授权 → 监听对象 → 推送 → 记账 → 看板

目标只有一个：**找出哪一步会让链路彻底走不通**（不是"体验不好"，是"根本跑不起来 / 跑起来也收不到账"）。

## 查出并修掉的 4 个真断点

### ① 白名单为空 → 服务端起不来（保留拦截，改对了提示）

首次装完点「启动服务」，`config_problems()` 和 GUI 的 `start_server()` 都会把"白名单里没有启用的采集端"当必填缺项拦住，而提示里还让"去配置页填推送密钥"——**那个字段早就删掉了**，客户顺着提示只会找一个不存在的东西。

按老板的要求，**拦截保留**（一条能推的客户端都没有，起了也收不到注），只把提示改成指路：

- 服务端自检：`还没有可用的采集端 API Key —— 去控制台「白名单」页点「新增」生成一条（微信号那一栏填采集端顶部显示的号）`
- GUI 启动：`白名单里还没有启用采集端 —— 去「白名单」页点「新增」生成一条（微信号填采集端顶部那个号，采集端那格右边可复制）`
- 老配置里还留着 `wx_push_secret` 的，按兼容模式放行，不误伤

### ② 采集端没填 API Key 也能"开始监听" → 静默 401

原来的逻辑：密钥留空时悄悄退回"用授权码 session_key 派生"的密钥去推。服务端白名单里是它自己生成的随机 Key，**永远对不上**，结果客户以为正在收账，实际一条都没进去，日志里全是一串 401。

现在的口径是**密钥不对就是不对，不留退路**：

- `app.py`：`cfg.secret` 为空且不是 dry-run → 直接 `return 4`，弹框写清四步（白名单新增 → 复制 Key → 配置页粘贴保存 → 开始监听）
- 只想先采集不推送（清空推送地址）仍然放行
- `gui._push_sign_key()`（点「测试地址」时取密钥的地方）**删掉了派生分支**：只认配置页「服务端 API Key」输入框或已保存的 `cfg.secret`，都没有就直接回
  `还没填服务端 API Key。到服务端「白名单」页点「新增」，点那一行的「复制 Key」，粘到本页「服务端 API Key」后点「保存」`
- 授权码在这条路径上只用来取微信号（`X-Wx-Cust` 靠它索引白名单），取不到照样能测，服务端会回"没带微信号"

### ③ 时间戳超窗混在"签名或时间戳不对"里

新装机器系统时间不准是 401 的头号原因，笼统报错只能靠猜。现在 `wx_hook` 先单独判 `abs(now - ts) > WX_SKEW_SEC(300)`，回执直接给秒差：

> 时间戳超窗：两边差了 900 秒（超过 300 秒就拒），把采集端那台机器的时间同步一下再试

**同机部署不会碰到**：时间戳由采集端那台机器生成，服务端用自己时钟算差值，同一台电脑差值≈0。只有采集端和服务端分装两台机器、且那台机器慢/快超过 5 分钟（主板电池没电、手改过时间、时区没设对）才会触发。

### ④ 签名不符的 reason 没指向真凶

现在回：

> 密钥对不上：采集端「配置」页的「服务端 API Key」要与这一行的一致

## 顺带修的

- 白名单表**去掉「客户」列**（客户编号早已不用）：列数 8 → 7，`_white_click` 的复制列由 `#8` 改 `#7`。不改的话点「复制」会点空——就是之前报过的"复制点击无效"同类问题（列偏移）。
- 空名单模式文案："否则服务起不来" → "否则采集端推不进来"。
- 账号下拉不再是"只有账本 / 上报过会话清单"的号：`main.all_accounts()` 与 `msb_view.whitelist_accounts()` 都并入白名单里启用的 `wechat_id`。首次安装两者皆空时，手工记账 / 文本记账的账号下拉不会再是空的。
- `从这里开始.txt` 按新流程整份重写（5,274 字节）：① 放 EXE ② 填大模型 Key ③ 启动 ④ 白名单新增（微信号去采集端复制）⑤ 采集端（授权码、默认地址、API Key、测试、默认全部会话）⑥ 跨机器防火墙 → 数据目录 → 控制台功能 → 封盘 → 401 排查。

# 解析规则外置（2026-11-19）

## 为什么要做

Nuitka 出一次包要 1.5 小时，而客户那边最常遇到的问题就是"某个叫法认不出来"。
以前只能改代码重新编译，现在把两个规则文件从 EXE 里让出来，改完重启服务（3 秒）就生效。

## 文件在哪

```
%LOCALAPPDATA%\MarkSixBot\patch\
├── bet_rules.py      玩法识别与号码集合
├── manual_plays.py   手工记账的按钮表
├── 说明.txt          给客户看的简版说明
└── .seed.json        版本指纹（程序自己维护，别动）
```

首次启动服务端时自动释放，不用手工准备。加载顺序：

1. 用户目录 `patch\`（主位置）
2. EXE 同目录 `patch\`（整个文件夹拷走的便携场景）
3. EXE 内置的那份（兜底）

配置页「配置 → 解析规则（叫法）」能看到**当前实际用的是哪个文件**。

## 怎么加一个叫法

打开 `bet_rules.py`，找到 `PLAYS = sorted([...])` 那一段，照现有条目加一行。

两条路，按情况选：

**A. 只是换说法（号码集合不变）**

已有的 `Play` 条目里，把正则的词改宽就行。比如波色那条：

```python
Play("color", "波色", r"(红|蓝|绿|红区|蓝区|绿区)\s*(?:波色|波)?", _r_color, 65)
```

注意 `_r_color` 是按 `m.group(1)` 去 `COLOR` 里查的，加了"红区"必须同时给 `COLOR` 加一个键，
否则查不到会返回空集合、这笔会被判成"没号码"。更稳的做法是加新条目+新取号函数：

```python
def _r_color_alias(m, zodiac):
    word = m.group(1)
    return COLOR.get(word[0], [])      # 取第一个字，「红区」-> 「红」

Play("color_alias", "波色别名", r"(红区|蓝区|绿区)", _r_color_alias, 64)
```

**B. 新的组合（几个集合取交集）**

以"红波小单"为例 —— 波色 ∩ 大小 ∩ 单双：

```python
def _r_color_size_parity(m, zodiac):
    """红波小单 / 蓝大双：三个条件同时满足。"""
    color = COLOR.get(m.group(1), [])
    size = SIZE.get(m.group(2), [])
    parity = PARITY.get(m.group(3), [])
    return [x for x in color if x in size and x in parity]


PLAYS = sorted([
    # ...摘一部分...
    Play("color_size_parity", "波色大小单双", r"(红|蓝|绿)(小|大)(单|双)",
         _r_color_size_parity, 96),
], key=lambda p: -p.priority)
```

**优先级（priority）很关键**：数值越大越先匹配。
`红波小单` 这种复合词必须比它的组成词（`红` 65、`小` 50、`单` 45）高，
否则会被 `红` 先吃掉，只算成红波 17 个号。上面写 96 就是让它排在所有组成词之前。

## 改完怎么验

1. 配置页「解析规则」→ 点 **「检查规则文件」**
   - 通过 → 绿字，显示识别到几条玩法
   - 语法错 → 红字给行号，并把出错那行原文贴出来
   - 正则写错（`bad character range` / `multiple repeat`）→ 也能查出来
   - 没通过就别重启，服务还在用旧规则
2. 通过后「停止 → 启动」服务
3. 用主界面的 **「文本记账」** 弹窗试：粘一句原文，点「解析」（Ctrl+P），
   下面会显示明细和「N 个号 · 合计 X 元」—— 确认对得上再点「记账」。

## 升级新版本时怎么处理

- 客户没动过这两个文件 → 新版 EXE 启动时自动换成新规则，旧的存成 `bet_rules.py.bak-日期时间`。
- 客户自己改过 → 不覆盖，配置页提示"未随新版更新"。要换新版规则就点「恢复出厂规则」。
- 想手工退回 → 删掉 `patch\` 里那两个文件，重启即用 EXE 内置版。

## 什么情况还得改代码重编

| 类型 | 例子 | 能配置 |
|---|---|---|
| 纯别名 | 红区 = 红波 | 能 |
| 已有集合的交/并 | 红波小单、鼠牛 | 能 |
| 新的号码集合 | 全新的号码分类 | 半能（得手工维护号码清单） |
| 计钱方式 | 按倍数、阶梯价、连环注 | 不能 |
| 句子结构 | 一句话多个玩法、省略主语、引用上一条 | 不能 |
| 特殊规则 | 和值、带权重、要查开奖结果才能定 | 不能 |

后面三类只能改代码，但改的是 `patch\bet_rules.py` —— 走外置这条路，**不用重编 EXE**。

## 技术细节（给自己看）

- 编译脚本用 `--nofollow-import-to=bet_rules,manual_plays` 把这两个模块排除出 EXE，
  同时用 `--include-data-files` 把原脚本塞进包里的 `patch_seed\`（兜底 + 释放模板）。
- `patch_loader.install()` 在第一次 `import bet_rules` 之前执行，先注册到 `sys.modules` 再 `exec_module`，
  这样 `manual_plays` 内部 `import bet_rules` 拿到的是同一份。
- 加载失败会把 `sys.modules` 回滚，让正常 import 拿到内置那份，服务不会因为一个缩进错误起不来。
- 校验 (`validate`) 用独立命名空间试加载，不碰正在运行的模块。

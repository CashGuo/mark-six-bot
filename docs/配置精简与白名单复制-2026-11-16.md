# 配置精简 + 白名单复制（2026-11-16）

## 一、配置页去掉「推送密钥」

验签早就整体交给「白名单」页了（每个采集端一把 API Key + 有效期 + IP 限制），
配置页再留一个「推送密钥」是两套东西并存，说不清到底认哪个。现在删掉。

### 连带处理

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| 配置页「采集端与验签」组 | 有「推送密钥」输入框 | 只剩「端口」 |
| `save_cfg()` | 把输入框的值写进 `wx_push_secret` | 读旧配置原样写回，不回空、不清值 |
| `start_server()` 必填校验 | 白名单空 + 密钥空 → 报缺项 | 白名单里没有**启用**的条目，且老配置里也没有兜底密钥 → 报「白名单里还没有启用的采集端」 |
| 白名单页顶部模式文案 | 名单空一律显示「兼容模式：还在用配置页那把密钥」 | 名单空且有老密钥 → 「兼容模式：…还在用老配置里那把密钥（建议「新增」换成 API Key）」；名单空且无老密钥 → 红字「还没有采集端：点「新增」生成 API Key，否则服务起不来」 |

**为什么不在服务端彻底删掉 `wx_push_secret`**：老配置里可能正靠它跑着。
服务端保留兜底读（白名单为空时用它），界面不再暴露 —— 新装的人只会走白名单这一条路。

## 二、白名单「复制」点了没反应

### 排查结论

源码里这条路径是通的。用隔离实例（临时数据目录 + 临时端口）断言过：

- `identify_column` 落在第 8 列 → `#8`，`identify_row` 落在行上 → 命中；
- 点完剪贴板里确实是 64 位明文 Key；
- 提示为「已复制 g111 的 API Key（64 位）」。

所以没反应的现实原因大概率是这两种之一：

1. **跑的是 exe**：`build\out\MarkSixBot.exe` 还是 11-16 07:19 编译的那版，
   不含之后所有改动（含这版复制提示与按钮）。要用新行为必须重编译。
2. **最后一列被裁**：列宽合计 965，125% 缩放的笔记本上窗口会窄一圈，
   最右那列刚好贴着边框，点到框外就什么都不会发生。

### 改了什么

- 列宽全部收紧：`secret 140→120`、`ip 130→110`、`last 140→120`，合计 965→830，
  给窄窗口留出余量（Treeview 默认 stretch，实际会按比例摊开填满）；
- 底部按钮条新增 **「复制 Key」**：选中一行 → 点按钮 → 复制，不用去点那一列；
- 两个入口共用 `_copy_key(wid)`，提示文案统一为
  「已复制 xxx 的 API Key（64 位），粘到采集端「配置」页即可」。

### 实测

| 操作 | 结果 |
| --- | --- |
| 点第 8 列「复制」 | 剪贴板 = 64 位 `A…`，提示「已复制 g111 的 API Key（64 位）…」 |
| 选中第二行点「复制 Key」按钮 | 剪贴板 = 64 位 `B…`，长度 64，提示同上（g222） |
| 配置页是否还有「推送密钥」 | `v_secret` 已不存在，控件里没有该输入框 |
| 白名单页模式文案 | 有启用条目 → 「严格模式：只接收名单内的采集端」 |

## 三、注意

以上都是 `server_gui.py` 的改动，**已打包的 exe 不含**。
要让客户机器上看到，得重新编译（`build\build_exe.ps1`，约 70 分钟）。

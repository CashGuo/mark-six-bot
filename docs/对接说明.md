# 记账中台 对接说明

面向要接这套服务端的第三方系统（或自己写采集端的人）。采集端用 WxPushTool 的话，这些都已经在界面里，不用看本文。

## 一、地址与端口

默认 `http://127.0.0.1:8899`。局域网访问用本机 IP，例如 `http://192.168.31.153:8899`。
端口可在控制台「配置」页改（改完要停止→启动）。

| 接口 | 方法 | 用途 | 谁能访问 |
|---|---|---|---|
| `/wx/hook` | POST | 采集端推送消息批次 | 任意（靠签名） |
| `/wx/contacts` | POST | 采集端上报会话清单 | 任意（靠签名） |
| `/wx/targets` | GET | 采集端拉取监听对象 | 任意（靠签名） |
| `/health` | GET | 存活探测，返回纯文本 `OK` | 任意 |
| `/` | GET | 网页看板 | 任意 |
| `/api/*` | GET/POST | 界面用接口（仪表盘、账号、清单、改 targets） | **仅本机**（127.0.0.1/::1） |
| `/top` `/status` `/recent` `/logs` `/backup` `/reset` | - | 运维与排障 | 任意 |

`/api/*` 里除了 `/api/dashboard` 是看板自己调的，其余都只认本机，避免把客户的全部账目摊在局域网上。

## 二、验签（两套规则，别混）

密钥：服务端 `%LOCALAPPDATA%\MarkSixBot\config\server.json` 的 `wx_push_secret`（出厂已内置，与采集端同一串，配置文件里改了以文件为准）；多采集端时按请求头 `X-Wx-Cust` 去 `wx_account_secrets` 里查，查不到退回全局密钥。

### 1. POST 报文（`/wx/hook`、`/wx/contacts`）

```python
ts  = str(int(time.time()))
sig = hmac.new(secret.encode(), f"{ts}.".encode() + raw_body, sha256).hexdigest()
```

- `raw_body` 必须是**原始字节**，不能用重新序列化后的 JSON（空格、键顺序变了签名就变）。
- 请求头：
  - `X-Wx-Timestamp: <ts>`
  - `X-Wx-Signature: <sig>`
  - `X-Wx-Cust: C0001`（可选，多采集端时用）
  - `Content-Type: application/json`

### 2. GET 请求（`/wx/targets`）

```python
sig = hmac.new(secret.encode(), f"GET.{path}.{ts}".encode(), sha256).hexdigest()
```

`path` 是**不含 query** 的路径（`/wx/targets`）。`?account=xxx` 不参与签名。

时间戳容差 `wx_skew_sec`，默认 300 秒，超出即 401。

## 三、推送报文（POST /wx/hook）

```json
{
  "batch_id": "b-20261112-2130",
  "account": "j693395002",
  "messages": [
    {
      "msg_id": "wxid_abc_10086",
      "msg_type": "文本",
      "target_id": "12345678@chatroom",
      "chat_id": "12345678@chatroom",
      "chat_name": "某某群",
      "sender": "wxid_xxx",
      "sender_name": "张三",
      "create_time": 1762000000,
      "content": "01 07 13 各50，25号100"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `msg_id` | 是 | 全局唯一。服务端用它去重，重复的直接 `skipped` |
| `content` | 是 | 原文。空内容或只有 `[图片]` 这类占位符会被跳过，不消耗 AI |
| `msg_type` | 否 | 只有「文本」会记账；「系统消息」及图片/文件等一律 `skipped` |
| `account` | 否 | 微信号。决定数据落在 `state\<account>\`。报文级和消息级都可给，消息级优先 |
| `target_id`/`chat_id` | 否 | 会话 ID，参与跨账号内容指纹 |
| `chat_name` | 否 | 群名/好友名，看板展示用 |
| `sender`/`sender_name` | 否 | 发送人，看板「发送人」列用 |

响应：

```json
{"ok": true, "count": 1, "recorded": 1, "unparsed": 0, "skipped": 0, "account": "j693395002"}
```

- `recorded` 解析出号码金额并记账
- `unparsed` 没解析出（原文进 `unparsed.jsonl`）
- `skipped` 重复 / 非文本 / 空内容 / 跨账号重复

### 去重两层

1. `msg_id`：全局挡同一份重复推送。
2. 内容指纹：`hash(target_id + create_time + sender + content)`。**同一群被两个微信号同时监听**时，两条消息的 `msg_id` 不同，靠这一层挡掉第二笔。

## 四、会话清单（POST /wx/contacts）

```json
{
  "account": "j693395002",
  "cust": "C0001",
  "hash": "abc123",
  "generated_at": 1762000000,
  "items": [
    {"chat_id": "12345678@chatroom", "name": "某某群", "type": "群聊", "msg_count": 128}
  ]
}
```

整份覆盖，天然幂等。`hash` 由采集端算，内容没变就别反复上报。
只上报**有过会话**的对象——没有会话的对象消息不会落库，监听了也收不到。

## 五、监听对象（GET /wx/targets）

请求：`GET /wx/targets?account=j693395002`，带 GET 签名。

```json
{"version": 8, "updated_at": "2026-11-12 21:00:00",
 "targets": [{"id": "*", "name": "全部会话"}],
 "account": "j693395002"}
```

- `version` 必须比采集端本地的大才覆盖。采集端只在版本变化时重写本地 `targets.json`。
- 特殊 id `*` = 监听全部会话（含以后新增的群和朋友，公众号排除）。
- 常规 id 就是 chat_id；采集端按 id 过滤，不在列表里的消息不推送。

改监听对象：`POST /api/targets`（仅本机），或在看板界面勾选。

## 六、运维接口

| 接口 | 说明 |
|---|---|
| `GET /status` | `{"accounts":[...], "grand_total":670.0, "records_today":6, "verify_enabled":true, ...}` |
| `GET /top` | 各号码累计风险 Top 10（纯文本） |
| `GET /recent` | 最近记账明细 |
| `GET /api/dashboard` | 看板数据（账号/合计/今日） |
| `POST /backup` | 立即备份 |
| `POST /restore/<YYYY-MM-DD>` | 恢复到某天备份 |
| `POST /reset?account=` | 清某账号（需带 account，避免误清全部） |

## 七、自助采集端的最小接入清单

1. `GET /wx/targets` 拿监听列表（版本变大才更新本地缓存）。
2. 监听到新文本消息 → 组报文 → 按「POST 报文」规则签 → `POST /wx/hook`。
3. 会话清单有变动才 `POST /wx/contacts` 上报。
4. 失败重试：网络/5xx 指数退避重试；401 是密钥问题，不要重试；429 退避。
5. 每条消息的 `msg_id` 要稳定（同一条消息重推必须同 id），否则服务端会重复记账。

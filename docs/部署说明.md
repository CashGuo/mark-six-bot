# 记账中台 部署说明

> 服务端 = 原「接收端」。它只做三件事：接采集端推过来的微信消息、让大模型解析出下注内容、记账并出网页看板。
> 从这一版开始它是**绿色免安装**的单文件程序：不装 Python、不建 venv、双击即用。

## 一、交付包里有什么

```
MarkSixBot.exe          主程序（服务端 + 控制台，同一个文件）
从这里开始.txt          客户看的一页纸
```

就这两个文件。EXE 放哪都行（桌面、D 盘、甚至 `C:\Program Files`），
配置、账本、日志**全部**写用户目录：

```
%LOCALAPPDATA%\MarkSixBot\
├─ config\server.json     配置（第一次启动自动生成出厂值，推送密钥已预填）
├─ config\wx_clients.json 授权客户清单
└─ data\                  账本 / 消息流水 / 日志 / 每日备份
```

换版本只替换 EXE，这个目录不动，账本不会丢。

## 二、部署步骤

1. 把 `MarkSixBot.exe` 放到一个固定位置（例如 `D:\MarkSixBot\`）。
   EXE 本身不写任何文件，所以放只读目录也能跑。
2. 双击 `MarkSixBot.exe`，弹出「记账中台」。第一次启动会自动建好 `%LOCALAPPDATA%\MarkSixBot\config\server.json`，
   **推送密钥已经是出厂值**，和采集端对得上，不用手工填。
   打包是压缩的 onefile（约 28 MB），首次启动会把内部解到 `%TEMP%`，会比源码态慢几秒，属正常。
3. 「配置」页只有两项需要动（都可留空）：
   - **API Key**：客户自己的大模型 Key；只有需要「模型兜底」才填，接口地址与模型名已预填
   - **多客户密钥**：只有接多个采集端时才填，格式 `C0001:密钥A,C0002:密钥B`（不填就用出厂密钥）
4. 点「保存配置」→「启动服务」。状态卡变「运行中」即成功。
5. 点「打开看板」验证网页能出记账界面。
6. 勾选右下角「开机自动启动」（写 `HKCU\...\Run`，只对当前用户生效，不需要管理员）。
7. 在采集端把推送地址改为 `http://<本机局域网IP>:8899/wx/hook`，targets 地址改为 `http://<本机局域网IP>:8899/wx/targets`，然后重启监听。

> 推送密钥为什么随 EXE 内置：它是采集端→服务端的 HMAC 签名密钥，两端必须逐字符一致，
> 采集端那串本来就随授权下发，让客户再手工复制一次只会出错（401 invalid signature）。
> 换采集端密钥时，改 `%LOCALAPPDATA%\MarkSixBot\config\server.json` 里的 `wx_push_secret` 即可，配置文件优先。

## 三、配置项说明（%LOCALAPPDATA%\MarkSixBot\config\server.json）

| 键 | 含义 | 默认 |
|---|---|---|
| `port` | 监听端口 | 8899 |
| `host` | 监听地址 | 0.0.0.0（局域网可达） |
| `wx_push_secret` | 单采集端推送密钥 | 出厂已内置 |
| `wx_account_secrets` | 多采集端映射 `C0001:密钥A,C0002:密钥B` | 空 |
| `wx_skew_sec` | 签名时间戳容差（秒） | 300 |
| `llm_api_key` | 大模型 Key | 空 |
| `llm_base_url` | OpenAI 兼容接口地址 | 阿里云百炼 MaaS |
| `llm_model` | 模型名 | qwen3.8-flash |
| `llm_thinking` | 思考模式 0/1 | 0 |
| `llm_timeout` | 单次解析超时（秒） | 60 |

优先级：**真实环境变量 > `%LOCALAPPDATA%\MarkSixBot\config\server.json` > 内置默认**。
只有 `server.json` **不存在**时才会去读老的 `.env`——这样客户在界面上改的值不会被 `.env` 里的旧值悄悄盖掉。

改配置必须在控制台里「停止服务」→「启动服务」，因为 Flask 的常量是进程启动时读的。

## 四、为什么这样设计（改造前的四个坑）

| 原来的做法 | 后果 | 现在 |
|---|---|---|
| `BASE_DIR = Path(__file__).parent` | 打包成 onefile 后 `__file__` 是**临时解包目录**，退出即清空，账本全丢 | `msb_paths.py` 用 `__compiled__`/`sys.frozen` 判断，编译态取 EXE 自身路径，数据固定写 `%LOCALAPPDATA%` |
| `.env` 靠 `load_dotenv()` 按当前工作目录找 | 从快捷方式/开机自启启动时找不到，密钥全空 | 配置固定 `%LOCALAPPDATA%\MarkSixBot\config\server.json`，与工作目录无关 |
| 缺 `WX_PUSH_SECRET`/`LLM_API_KEY` 在**模块导入期** `raise ValueError` | 双击 EXE 瞬间闪退，一个字提示都没有 | 改成 `config_problems()` 返回人话清单，编译态弹 MessageBox |
| 双击只有 Flask 黑窗，关窗即停 | 客户不知道看板在哪、不会自启、改不了配置 | Tk 控制台 + 起停按钮 + 开机自启 + 看板直达 |

## 五、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击没窗口 | 缺 VC 运行库 / 被杀软拦 | 看事件查看器；把目录加进杀软白名单 |
| 弹「配置不完整」 | 大模型 Key 没填（只影响模型兜底，规则解析不受影响） | 控制台「配置」页补上 |
| 弹「已经有一个服务端在跑」 | `.bot.lock` 是活的另一个实例 | 先「停止服务」；确认没进程后删掉 `data\.bot.lock` |
| 弹「端口起不来」 | 8899 被占 | 换端口，采集端地址同步改 |
| 采集端 401 invalid signature | 两边密钥不一致（含空格/换行） | 逐字符比对；注意报文签名与 GET 签名是两套规则 |
| 看板 200 但没数据 | 采集端没监听任何会话，或 targets 是空列表 | 采集端勾「监听全部会话」或勾具体会话 |
| 日志里有「跨账号重复」 | 两个号同时监听了同一个群，内容指纹生效 | 正常行为，不是错误 |

日志位置：`%LOCALAPPDATA%\MarkSixBot\data\logs\bot_<日期>.log`（UTF-8）。
控制台「数据」页只看最近 40 行；要全量点「打开日志」。

## 六、备份与恢复

- 每天自动备份到 `data\backups\`（保留最近若干天）。
- 手动：HTTP `POST /backup`。
- 恢复：`POST /restore/<YYYY-MM-DD>`。
- 整机迁移：拷走 `%LOCALAPPDATA%\MarkSixBot\data` 整个目录即可，账本/清单/去重表都在里面。

## 七、已知边界

- 服务端**没有**授权校验（与采集端不同）。采集端负责 license，服务端只认推送密钥。若后续也要一客一码，需要另加。
- 只处理文本消息；图片/文件/系统消息只计数不记账。
- 无控制台模式下（打包版 `--headless`）`sys.stdout`/`sys.stderr` 是 `None`：程序内部已兜成空输出，不会再因此闪退；想看到输出请进 `data\logs\bot_<日期>.log`，配置类错误会弹框。
- 首次启动若配置缺项，控制台会在点「启动服务」时弹「配置还没填」并列出缺哪几项，不会静默退出。
- 配置和账本都在 `%LOCALAPPDATA%\MarkSixBot\`，**不在 EXE 所在目录**。把 EXE 挪走也不会丢账；
  反过来，想换电脑就把整个 `%LOCALAPPDATA%\MarkSixBot` 目录拷过去。
- 老部署（配置还在程序目录 `config\server.json`）第一次用新 EXE 启动时会自动复制到用户目录，之后以用户目录为准。

## 二、核心口径：界面上只有一种算法

**每个被选中的号码，各记一个金额**。不摊开、不折算。

- 点 `06` 填 50 → 06 记 50
- 点 `06 18` 填 50 → 各 50，共 100
- 点「牛」填 100 → `06/18/30/42` **各 100，共 400**
- 点「大」填 50 → 25–49 共 25 个号 **各 50，共 1250**
- 点「大」+「单」填 50 → 大单共 13 个号各 50，共 650

`_split(pool=True)` 那套摊开逻辑整段删掉，界面与文本规则、与账本三者永远同一个结果。

| **大小** | 大 / 小 | 25 / 24 |
| **波色** | 红波 / 蓝波 / 绿波 | 17 / 16 / 16 |
| **波色单双** | 红单 / 红双 / 蓝单 / 蓝双 / 绿单 / 绿双 | 8 / 9 / 8 / 8 / 9 / 7 |
| **波色大小** | 红小 / 红大 / 蓝小 / 蓝大 / 绿小 / 绿大 | 10 / 7 / 7 / 9 / 7 / 9 |
| **合数** | 合数单 / 合数双 | 25 / 24 |
| **尾数** | 0尾 1尾 2尾 3尾 4尾 5尾 6尾 7尾 8尾 9尾 | 4~5 个/尾 |
| **头数** | 0头 / 1头 / 2头 / 3头 / 4头 | 9 / 10 / 10 / 10 / 10 |
| **五行** | 金 / 木 / 水 / 火 / 土 | 10 / 10 / 9 / 12 / 8 |
| **家禽野兽** | 家禽 / 野兽 | 25 / 24 |
| **生肖** | 12 个（马蛇龙兔虎牛鼠猪狗鸡猴羊） | 4~5 个/肖 |
| **号码** | 号码盘 1–49 直接点 | 1 |

> 「大单 / 小双 / 红小」这类不需要单独按钮：点「大」再点「单」就是大单，点「红波」再点「单」就是红单，结果和文本规则里的交集完全一致。

### 3.2 三种选法怎么叠加（关键规则）

| 你点了 | 怎么算 | 例子 |
|---|---|---|
| 只点具体号码 | 这几个号 | 点 `06 18` → 2 个号 |
| 点多个生肖 | **并集** | 点「牛」「马」→ 4+5 = 9 个号（和文本 `牛马各10` 一致） |
| 点多个玩法 | **交集** | 点「大」「单」→ 13 个号（= 大单） |
| 生肖 + 玩法 | **交集** | 点「牛」「马」再点「大」→ 牛马 9 个号里的大号：`25 37 49 30 42` 共 5 个 |
| 玩法 + 玩法 + 玩法 | 继续交集 | 「红波」+「单」+「小」→ 红小单 |
| 具体号码 + 任何条件 | 以号码为准，条件自动清空 | 点 `06` 时，生肖和玩法选择被清掉（避免"到底算哪个"的歧义） |

**交集为空**（比如「红波」+「蓝波」、或「大」+「小」）：号码盘不亮任何格，顶部红字提示「红波和蓝波没有共同的号」，加不进清单。

### 3.3 顶部实时回显（防记错的关键）

选择一变，标题下面就显示这一行：

```
条件：牛 + 马 ∩ 大         → 5 个号：25 37 49 30 42   每号 100   合计 500
```

点「大」这种一次圈 25 个号的玩法时，这一行是唯一能让用户当场确认"我到底压了多少号、多少钱"的东西 —— 25 号 × 50 = 1250，很容易被当成 50 块。

## 五、交互流程

1. 选市场（默认澳门），确认挂谁名下（默认带出最近记账的客户）。
2. 点号码 / 生肖 / 玩法 → 顶部回显条件与结果，号码盘同步高亮。
3. 点快捷金额或输入 → `Enter` 或「加入」。
4. 这一注进清单，行内显示每号金额与小计。
5. 继续加注（同一客户一次多注）。
6. 「记账」一次性提交全部；勾了连续记账就留在窗口继续下一笔。
7. 键盘：`Enter` 加入，`Ctrl+Enter` 记账，`Esc` 取消，选中行 `Delete` 删除。
8. 同一个玩法按钮再点一次＝取消该条件；生肖同理。

## 六、记账链路（不另起一套账本逻辑）

手工窗口不自己写账本，把清单拼成原文交给现有接口：

```
清单 → "牛各100；大单各50" → POST /api/quick_bet {text, chat, account, market}
                                ↓
                     record_bet：规则解析 → 分盘落账 → 写流水 → 期号归档
```

好处：只有一套落账逻辑，手记和微信推送不会算出两个结果；期号、港澳分盘、流水、撤销（`manual-<时间戳>` 的 msg_id）全部自动继承；流水 `text` 就是可读原文，事后对账能看出记了什么。

需要改一处：`/api/quick_bet` 加可选 `market` 参数（窗口明确选了香港就以香港为准，不传仍按文本里的「港/香/澳」判），`record_bet` 加同名覆盖，解析器不动。

「加入」时用本地 `bet_rules.parse_local` 直接算预览，和记账同一套规则、零延迟；拼出来的话解析不了就当场提示，不等到点记账才失败。

**注意**：拼出来的写法必须都是解析器已支持的形状（`牛各100`、`大单各50`、`06 18各50`），所以改完要拿这 44 个玩法逐个跑一遍回归。

## 十一、网页版手工记账（已实现）

看板（`/`）原来只有只读功能：今日已记账、今日未解析、最近记账、未解析、联系人清单下发，没有手工记账入口。这一节说的是新加的 `/manual` 页，它和窗口用的是**同一套规则**，不是照抄一份。

### 11.1 一份规则，两个界面

规则不再由界面各自计算，抽成 `manual_plays.py`：

| 函数 | 干什么 |
|---|---|
| `GROUPS` | 10 组共 43 个玩法按钮（窗口 `PLAY_GROUPS` 直接引用它） |
| `nums_of_play(code, mapping, cache)` | 一个玩法的号码集（靠 `bet_rules.parse_local` 反推，不手写号表） |
| `target(...)` | 号码优先；否则生肖并集 → 玩法交集 → 两者取交 |
| `compose_text(...)` | 拼出可解析的原文（`牛马`、`大单`、`06 18`） |
| `label_of(...)` | 清单标签（`牛（06/18/30/42）`） |
| `verify(...)` | 用解析器回读自检，拼错了当场发现 |
| `build(...)` | 算号 + 拼句 + 自检 + 金额校验，给出 `{ok,text,label,nums,each,total}` |
| `join_text / verify_join` | 多注拼整句、整句自检（重叠号码金额累加） |

窗口侧 `server_gui.py` 的 `_target/_compose_text/_label/_combo_name/_verify_join` 已全部改成委托这个模块；70 组条件（43 玩法 + 12 生肖 + 组合/交并/号码）逐组比对，窗口与模块结果完全一致。

生肖的书写顺序统一成传统的 **鼠牛虎兔龙蛇马羊猴鸡狗猪**（`ZODIAC_ORDER`）。盘面行序是按 01~12 所属排的（马在前），直接拿来拼句会拼出「马牛」，和客户写「牛马」相反，所以拼句和标签另用传统序。

### 11.2 网页界面（`templates/manual.html`，路由 `/manual`）

版面按窗口摆：

- 顶栏：标题、`澳门 | 香港` 分段按钮（默认澳门）、账号下拉（默认选钱最多的那个账号）、「挂在谁名下」（可下拉可选可手打）、`马年 · 43 个玩法`、回看板。
- 左栏：7×7 号码盘（按波色上色）、12 生肖（多选取并集）、10 组 43 个玩法（多选取交集）、底部提示条「条件 → N 个号 · 每号 X · 合计 Y」。
- 右栏：金额输入 + 快捷 10/20/50/100/200 + 加入、清单表格（分类/内容/每号/合计/删除）、合计大字、连续记账勾选、清空、记账。

**网页不自己算号码**：条件一变就 `POST /api/manual/build`（amount=1）拿 `nums` 去高亮和提示，带请求序号丢弃过期结果。交集为空时提示条转黄、写着「没有共同的号，换个选法」，「加入」按钮变灰。

快捷键：Ctrl+Enter 记账、Delete 删选中行、金额框回车加入；合计超过 1000 元先 `confirm()`。

### 11.3 接口

| 接口 | 说明 |
|---|---|
| `GET /manual` | 页面（本机来源，`_LOCAL_REQUIRED`） |
| `GET /api/manual/meta` | 玩法表（含每个玩法号数）、12 生肖、49 号码、账号、常用对象、`default_account` |
| `POST /api/manual/build` | `{nums,zodiacs,plays,amount}` → `{ok,text,label,nums,each,total,reason}`，只算不记 |
| `POST /api/manual/submit` | `{notes:[{text,each,nums}], chat, account, market}` → 真记账 |

`/api/manual/submit` 先把清单用 `join_text` 拼成整句、`verify_join` 判断整句通不通：

- 通 → 一次 `record_bet`（msg_id `manual-<毫秒>`）；
- 不通 → 逐注 `record_bet`（msg_id `manual-<毫秒>-<i>`），失败的汇总返回。

返回 `{ok, market, market_name, account, numbers, total, notes, text, archived_issue, detail}`。落账仍走 `record_bet`，所以期号归档、港澳分盘、流水、撤销全都自动继承。

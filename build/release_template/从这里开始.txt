记账中台 使用说明
========================================

它是干什么的
    接采集端（WxPushTool）推过来的微信消息 → 解析下注内容 → 记账 → 网页看板。
    不装 Python，双击就能用；数据留在本机，不上传。

----------------------------------------
第 1 步：双击
    把 MarkSixBot.exe 放到一个固定位置（比如 D:\MarkSixBot\），以后别删别挪。
    双击它 —— 会弹出「记账中台」窗口。
    看到窗口就说明程序本身没问题。

    第一次启动会自动建好配置，都在：
        %LOCALAPPDATA%\MarkSixBot\config\server.json
    EXE 放哪个盘都行，配置和账本都在用户目录，不受影响。

第 2 步：填可选项（都能留空）
    窗口「配置」页：
      推送密钥   ← 已经内置好了，不用动（和采集端的是同一串，改采集端时才来改这里）
      多客户密钥 ← 只有接多个微信号的采集端时才填，格式 C0001:密钥A,C0002:密钥B
      API Key    ← 你自己买的大模型 Key；不填也能用，规则认得出来的照常记，
                   规则认不出的才需要它兜底（接口地址默认已填好，一般不用改）
    改完点左下「保存配置」。

第 3 步：启动服务
    点「启动服务」，状态卡会从「未运行」变成「运行中」。
    再点「打开看板」，浏览器里就是记账界面。
    这个控制台窗口关掉不影响后台，服务照旧跑。

第 4 步：把采集端指过来
    打开采集端 WxPushTool 控制台 →「推送与采集」页 → 推送地址改成：
        http://<这台电脑的局域网IP>:8899/wx/hook
    本机自测就填 http://127.0.0.1:8899/wx/hook。
    采集端那边的 targets 接口地址同理，改成 http://<IP>:8899/wx/targets。
    改完在采集端「停止」再「开始监听」。

----------------------------------------
数据在哪
    %LOCALAPPDATA%\MarkSixBot\
        config\server.json                  推送密钥、端口、大模型 Key
        config\wx_clients.json              授权客户清单
        data\state\<微信号>\numbers_state.json    各号码累计（澳门盘）
        data\state\<微信号>\numbers_state_hk.json 各号码累计（香港盘）
        data\state\<微信号>\records.jsonl         每一笔记账明细
        data\state\<微信号>\issues\               已归档的历史期
        data\contacts\<微信号>.json              采集端上报的会话清单
        data\targets\<微信号>.json               监听对象
        data\logs\bot_<日期>.log                 运行日志
        data\backups\                            每天自动备份

    换新版本只换 EXE，这个目录不动，账本不会丢。
    想搬机器：把整个 MarkSixBot 目录拷过去即可。

----------------------------------------
控制台里能干的事
    「总览」页  ：金额汇总、澳门/香港号码盘、总额排序、最近记账（可按账期看）
    「配置」页  ：推送密钥 / 多客户密钥 / 端口 / 大模型 Key / 接口地址 / 模型名
    「消息」页  ：收到的每条消息解析结果，可按账期过滤、可撤销某一笔
    「白名单」页：授权客户的管理
    底部按钮    ：启动服务 / 停止服务 / 保存配置 / 打开看板 / 打开日志
    右下角      ：☐ 开机自动启动（勾上以后开机静默后台跑，不弹窗口）

    改配置后要「停止服务」→「启动服务」才会生效（配置是启动时读的）。

----------------------------------------
接多个微信号（多个采集端）
    每台采集端一个客户编号（C0001、C0002…），在「配置」页的多客户密钥里填：
        C0001:密钥A,C0002:密钥B
    然后两台采集端的推送地址都指向这台服务端。
    看板右上角的下拉可以看单个号，也可以看「全部账号（合计）」。
    同一个群的同一条消息被两个号都收到时，服务端会按内容指纹去重，不会记两笔。

----------------------------------------
出问题先看这三处
    1. 状态卡一直「未运行」：看「消息」页和日志，最常见是端口 8899 被别的程序占了，
       在「配置」页换个端口（采集端的推送地址也要跟着改）。
    2. 采集端推了但没记账：确认两边「推送密钥」完全一致（多一个空格都会验签失败），
       再看日志里有没有 signature 相关报错。
    3. 有消息但记不上：日志里会写「未解析」，原文留在 unparsed.jsonl 里，
       多半是那句话里没有号码/金额，换个说法试试。

    网页看板打不开但服务在跑：试试 http://127.0.0.1:8899/ ，端口可能改过。
    服务端和采集端不在同一台机器时，防火墙要放行 8899 端口。
